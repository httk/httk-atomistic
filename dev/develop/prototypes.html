Material-information levels¶

httk-atomistic describes a crystalline material at several levels of information, organised as a matrix. The rows differ in how much geometrical information is kept; the columns differ in whether the site identities are anonymous placeholders or real chemical species. Each cell is a value family (a backend value plus its views) in httk.atomistic.

The top row keeps only how many sites each species class occupies; its assigned cell is deliberately empty. ChemicalFormula (with the composition-based AnonymousFormula) sits outside the matrix as the occupation-based composition: unlike Formulatype, it weights each site by its occupancy (see Composition and formula families). The bare row keeps a standard-setting space group and its occupied Wyckoff positions. The geometrical-class row adds an exact fundamental-domain representative, an externally assigned nonempty discriminator string, or both. The bottom row fixes the exact continuous degrees of freedom (cell parameters and free coordinates). Reading upward loses geometrical information; reading right assigns real species to anonymous placeholders.

BarePrototype and BareProtostructure cannot carry a representative or discriminator. Prototype and Protostructure require at least one of those refinements. Refined equality and content identity include them, so a representative-only value never equals a discriminator-only value. Ordinary recognition and label parsing return bare values; refinement is always explicit.

from httk.atomistic import BareProtostructure, BareProtostructureView, Protostructure

bare = BareProtostructure(225, [("a", "Na"), ("b", "Cl")])
refined = Protostructure(bare.spacegroup, bare.occupations, discriminator="001")
assert BareProtostructureView(refined).unview() == bare
assert str(refined.label) == str(bare.label)
assert refined != bare

The representative’s continuous degrees of freedom are a class anchor, not exact-structure data: its coordinates and cell are retained exactly so the anchor can be reconstructed, while the structural key stays a coarse classification. A prototype or protostructure therefore corresponds to many exact structures — every realization that shares the class — whereas a Structuretype or a Structure fixes the continuous degrees of freedom and so names a single exact geometry. Prototype uses a FundamentalDomainTemplate representative and anonymous PrototypeOccupation values; Protostructure uses a FundamentalDomainStructure representative and real-species WyckoffOccupation values.

How the levels relate¶

The levels combine by adding one piece of information at a time. These are information-content relationships, not class inheritance:

  • BarePrototype + species assignment → BareProtostructure

  • BarePrototype + representative/discriminator → Prototype

  • BareProtostructure + representative/discriminator → Protostructure

  • Prototype + species assignment → Protostructure

  • Structuretype + species assignment → Structure

  • Projection onto class site counts → Formulatype

  • Projection onto composition → ChemicalFormula or AnonymousFormula

A bare view of a refined value retains its source, so rewrapping can recover existing refinement. Calling unview() explicitly materializes a standalone bare value; its discarded representative cannot be recovered. Refined views do not infer a class from bare values, raw structures, or label strings. Construct Protostructure(representative=asu) or Prototype(representative=template) to choose an exact class anchor explicitly.

Naming and capitalization¶

The canonical taxonomy terms are single-capital compound words: Formulatype, Prototype, Protostructure, and Structuretype; the broader Wyckoff-only families are BarePrototype and BareProtostructure. The suffix -type marks the anonymous-occupation column (Structuretype and Prototype are the anonymous counterparts of Structure and Protostructure; Formulatype has no assigned counterpart); the Bare prefix distinguishes cutoff-free Wyckoff classification from a refined geometrical class.

The word “Template” no longer names the exact anonymous family — that family is Structuretype. “Template” survives only for the exact fundamental-domain anonymous values used as class anchors and ASU keys: FundamentalDomainTemplate and ASUTemplate (and their view family, e.g. FundamentalDomainTemplateView). The name Prototype is the already-established term for what a fully systematic naming scheme would call a “templatetype”; there is no code alias for the latter (see Naming of httk₂ structural classes).

The older names survive as aliases for discoverability only; documentation and new code use the canonical names. AnonymousFormula and AnonymousFormulaView are no longer aliases: they name the composition-based anonymous formula, while Formulatype counts sites.

Dummy species¶

The anonymous exact values (Structuretype, FundamentalDomainTemplate, and the representative held by a Prototype) use a deliberately narrow dummy-species shape. The label is carried through the labels decoration and the species name; it is never encoded as a chemical symbol:

from httk.atomistic import Species
from httk.atomistic.models.structuretype.anonymize import dummy_species, is_dummy_species

species = dummy_species("A")
assert species == Species("A", ("X",), (1,), labels=("A",))
assert is_dummy_species(species)

is_dummy_species requires exactly one "X" chemical symbol, unit concentration, matching name/label, and no mass, attachments, charge, spin, original name, or concentration decoration. Consequently a species named A with labels=("other",) is not a dummy species. A BarePrototype carries anonymous class labels (A, B, C, …) directly, without dummy Species objects. A Prototype also uses these labels for its occupations; its optional representative contains dummy species.

Formula conveniences¶

Every structural family below the top row exposes anonymous_formula, the Formulatype of its class site counts, which is also the prefix of its label; the assigned families additionally expose formula, their composition. A Formulatype has no anonymous_formula attribute — it is the anonymous formula, rendered as its string value (str(FormulatypeView(...)), e.g. "A3B2"). Wyckoff-family counts use conventional Wyckoff multiplicities, and rendering removes a common GCD. The composition-based anonymous formula is AnonymousFormulaView(value):

from httk.atomistic import Structuretype, StructuretypeView

template = Structuretype(
    [[5, 0, 0], [0, 5, 0], [0, 0, 5]],
    [[0, 0, 0], [1 / 2, 1 / 2, 1 / 2]],
    species_at_sites=("A", "B"),
)
view = StructuretypeView(template)
assert view.anonymous_formula == "AB"
assert view.unwrap() is template

BareProtostructure is the Wyckoff-with-species key: it has no cell or coordinates. Equality uses its standard-setting space group and occupied Wyckoff positions with associated Species values, independent of construction order. BarePrototype is its anonymous counterpart. Both are hashable. Refined values additionally compare their representative and discriminator; values differing only in representative may hash alike but remain unequal.

Once their input views have been materialized, the four canonicalizers operate at the classification level:

from httk.atomistic import (
    canonical_bare_prototype,
    canonical_bare_protostructure,
    canonical_prototype,
    canonical_protostructure,
)

bare_assigned = canonical_bare_protostructure(bare_assigned_source)
bare_anonymous = canonical_bare_prototype(bare_anonymous_source)
refined_assigned = canonical_protostructure(refined_assigned_source)
refined_anonymous = canonical_prototype(refined_anonymous_source)

assert canonical_bare_protostructure(bare_assigned) == bare_assigned
assert canonical_bare_prototype(bare_anonymous) == bare_anonymous
assert canonical_protostructure(refined_assigned) == refined_assigned
assert canonical_prototype(refined_anonymous) == refined_anonymous

View materialization preserves the conversion boundaries in the table above, so a raw ordinary structure accepted by a bare view can first require tolerant spglib recognition. The bare minimization itself uses no geometry and enumerates finite exact letter-changing actions. The refined operations canonicalize an exact retained representative when one exists; with only a discriminator they canonicalize the bare base and retain that discriminator. A refined geometry terminal can demote special positions or collapse an exact supercell, operations for which a bare value has no geometry. Canonicalize the projected value when a canonical bare result is required; projection and canonicalization do not generally commute. For sites declared on their own Wyckoff letter, a canonical refined value’s label equals the canonical bare label as a string, species order included (a site declared on a more general letter than its point, e.g. on the general position at a special point, is demoted by the refined terminal only, so the labels then differ). Its representative (cell and sites) does not depend on the cell the input was given in, and its cell is right-handed. By default it is the crystal itself: a Sohncke group uses no mirror description, so the two hands of a crystal can get different labels (P4₂32 b and c). A P-1 representative is in its Niggli cell when every atom is on the general position; atoms on inversion centres can force the cell with the lexicographically least (a·a, b·b, c·c) among those keeping the canonical letters, which need not be reduced in the usual sense. FundamentalDomainTemplate.bare_prototype extracts the discrete anonymous key. The full procedure and retained-coordinate policy are specified in Canonicalization algorithms and reproducibility.

Labels¶

An httk label is a compact string encoding the information content of an unsuffixed AFLOW-style prototype label: a space group, its occupied Wyckoff letters, and the partition of those occupations into species classes. The single home of the notation is httk.atomistic.models.prototype.notation. The grammar is:

ANON_PEARSON_ITNUMBER_GROUP(_GROUP)*                 # prototype label
ANON_PEARSON_ITNUMBER_GROUP(_GROUP)*:NAME(-NAME)*    # protostructure label

A GROUP is the concatenation of one class’s Wyckoff letters, sorted alphabetically, a letter occupied k >= 2 times prefixed by the integer k (2e); count 1 is omitted. ANON is the anonymous formula (A, B, C, …) built in group order with per-group summed conventional multiplicities reduced by their overall GCD, so it is the Formulatype of the class site counts.

The prefix is also every level’s anonymous_formula, including for disordered or mixed-species occupations: a BareProtostructure with an equal Fe/Ni mixture on 225 a and O on b labels as AB_cF8_225_a_b:Fe0.5Ni0.5-O and its anonymous_formula is AB; only its composition-based AnonymousFormulaView is A2BC. Erasing it gives the BarePrototype AB_cF8_225_a_b, and so does BarePrototypeView(structure) for a structure carrying such species.

Species classes¶

Every level from Formulatype to Protonetstructure partitions the sites into the same species classes. Two species are in one class when they have the same key: the concentration of each chemical symbol other than vacancy, rounded to three decimals (half up; the vacancy is the remainder, stated or not), and the count of each attached symbol. The name, original name, labels, charges, spins, mass and concentration precision are not part of the key, so CIF site labels never split a class, an isotope is its element, and AgO (COD 1509688), whose CIF types Ag1 as Ag⁺¹ and Ag2 as Ag⁺³, has one silver class: AB_mP8_14_ab_e:Ag-O. The assigned levels store each species as its class species, which carries only the key; the loaded structure keeps its own species, names, labels and charges.

A class name is derived from the key alone, and the label parsers rebuild the key from it:

  • one constituent at rounded concentration 1: its symbol (Ti), the class of the fully occupied element;

  • otherwise the constituents in alphabetical order, each followed by its rounded concentration as its shortest decimal, always with a ., the vacancy and constituents that round to 0 omitted (Bi0.5Na0.5, Li0.76, Ag0.317Ga0.561, Li0.333);

  • attached atoms follow as symbol and count, the count always written and the symbols in alphabetical order (OH2, NH4, OH1, K0.5Na0.5C1H3).

A class name uses only letters, digits and ., so it never contains the / unusable in URLs and file names, the - that separates names, the : that starts the suffix, or the _, ~ and @ of the net. A species with the unknown symbol X (a dummy template species) is its own class, by name; assigned levels reject it.

Classes are compared by their rounded concentrations. Partially occupied sites therefore merge only when their occupancies agree to three decimals: two half-occupied carbon sites form one class C0.5, and so do 0.4996 and 0.5004, but the same sites refined as 0.49 and 0.51 form two. Occupancies that a file normalizes to fractions such as 83335/100004 are named by their rounded values (F0.833O0.167). The rounded constituents of one class can sum to slightly more than 1 (0.4995 and 0.5005 round to 0.5 and 0.501); such a class has no vacancy. Split positions of one atom with equal occupancies merge into one class (for example two half-occupied lithium positions 0.67 Å apart), and different Wyckoff orbits of one class are counted together, as for fully occupied sites.

Structuretype and templates are anonymized differently and keep their documented rules: they merge species by element, ignoring charges and attached atoms, and refuse disorder and partial occupancy. They can therefore differ from the structure’s own classes only where one element occurs with different attached atoms (O and OH2, or OH1 and OH2). Their element merge can then also change the recognized space group, since the merged sites may become equivalent.

The labels classify the structure of species classes, not the named species. Every label entry point (BareProtostructureView, BarePrototypeView, canonical_bare_protostructure, canonical_bare_prototype, the structure methods canonical_bare_protostructure() and canonical_bare_prototype(), canonical_asu_protostructure, canonical_asu_protostructure_assignments, Protostructure(representative=...) and Protonetstructure.from_asu) works on the structure in which every used species is replaced by its class. Two sites of one chemistry that differ only in name or charge are one class, and the class structure can have higher symmetry than the named one: Fe²⁺ at the origin and Fe³⁺ at the body centre of a cubic cell is A_cI2_229_a:Fe. A structure without an ASU is recognized as its class structure. A declared ASU keeps its declared symmetry while each of its species is its own class; when two of its species share a class, the class structure is recognized instead, and a declared representative becomes the canonical ASU of the class structure. So Protostructure(representative=canonical_asu(s)) gives the canonical label too. When the class structure has another space group or conventional cell, Protonetstructure.from_asu re-expresses the bonds, which name the declared sites, in the recognized symmetry; it raises when the bond set is not invariant under that symmetry. canonical_asu and canonicalize are structure canonicalizers: they keep the source species and the symmetry those have (P m -3 m here). A structure with a site occupied only by vacancy has no classes, so its Formulatype and labels raise.

A structure’s canonicalization preserves chirality by default: the canonical functions, the constructors, from_asu and the command line all default to preserve_chirality=True, and in a Sohncke group no mirror description is then used, so a crystal and its mirror image can get different labels (154 and 152, or in P4₂32 A3B_cP16_208_i_b:H-P and A3B_cP16_208_i_c:H-P). Pass preserve_chirality=False to the corresponding classification canonicalizer when a label should identify the two hands: mirror descriptions are then used and the higher member of an enantiomorphic pair moves to the lower one. The same policy is available through canonical_asu(preserve_chirality=False) and normalize_chirality; see Asymmetric units. Occupations given without a cell (BareProtostructure(...), BarePrototype(...) and the Protonettype and Protonetstructure constructors) are read in a right-handed basis of the standard setting. A declared ASU or representative in a left-handed cell is re-described as the same crystal in a right-handed one first; Protonetstructure.from_asu re-describes its bonds with it.

Important

The structure methods canonical_bare_protostructure() and canonical_bare_prototype() are the exception: they identify the two hands (they behave as preserve_chirality=False). They recognize and canonicalize the structure, then canonicalize its bare projection, so a crystal and its mirror image get the same label from them. Use the classification canonicalizers to keep the hand.

httk labels are not AFLOW labels¶

The httk group-ordering convention follows Formulatype: the class with the largest summed conventional Wyckoff multiplicity (its site count, not an occupancy-weighted amount) comes first; classes with equal counts are ordered lexicographically by their sorted Wyckoff-letter sequences; a remaining tie is broken by the species class name in a protostructure label. The anonymous symbols A, B, … are assigned in the same order, and the canonicalizers use the same key to choose among equivalent descriptions, so a canonical value and its label agree. This ordering is element-agnostic, so a protostructure label is exactly its erased prototype label plus the : species suffix. AFLOW, by contrast, orders the classes by element symbol alphabetically, so its unsuffixed prefix depends on the chemistry. The two are therefore genuinely different strings, and an httk label is not an AFLOW label.

The assigned-species classes expose both, as distinct properties: label (the httk convention, a BareProtostructureLabel for a bare value) and aflow_label (the AFLOW-style rendering, a plain str). For calcite, BareProtostructure(167, a:Ca, b:C, e:O):

from httk.atomistic import BareProtostructure, Species

Ca, C, O = Species("Ca", ("Ca",), (1,)), Species("C", ("C",), (1,)), Species("O", ("O",), (1,))
calcite = BareProtostructure(167, [("a", Ca), ("b", C), ("e", O)])
assert calcite.label == "A3BC_hR10_167_e_a_b:O-Ca-C"
assert calcite.aflow_label == "ABC3_hR10_167_b_a_e:C-Ca-O"

The httk label puts O on e (18 sites) first; Ca on a and C on b tie with 6 sites each and follow by Wyckoff letter. The AFLOW label orders the groups b, a, e to follow the alphabetical elements C, Ca, O.

Pearson symbol¶

The Pearson symbol is system + centring + count. The system letter follows the space group’s crystal system (a, m, o, t, h, h, c for triclinic through cubic, trigonal and hexagonal both mapping to h). The centring letter follows the centring type, with the base-centred variants A, B, C, and S folded to C (the A case fires for groups 38–41). The count is the conventional-cell site count, except a rhombohedral R setting — tabulated on hexagonal axes — divides it by three (and asserts divisibility). Calcite’s 30 conventional sites give hR10.

The 27th Wyckoff letter used by a few high-multiplicity settings (group 47’s eightfold orbit, internally 'α') renders as A and parses back from it; positionally a group token never collides with the leading anonymous formula.

Strict parser¶

The parser is strict and canonical-only: it resolves the standard setting, validates every Wyckoff letter, recomputes the Pearson symbol, the reduced anonymous counts, and the group ordering, and rejects any string that deviates from the recomputed canonical form. Suffix names must be canonical species class names and become their class species, so an element symbol becomes Species(name, (name,), (1,)). Round trips are pinned in both directions: parse(render(x)) == x for bare values and render(parse(s)) == s for canonical strings. This mirrors parse_anonymous_formula for Formulatype. Use parse_bare_prototype_label and parse_bare_protostructure_label from the notation module, or the corresponding bare views. Parsing refined label text returns only its bare classification; the text cannot encode its refinement.

Canonical vs plain labels¶

Any faithful render of an object is the prototype or protostructure label. The canonical prototype or protostructure label is the one obtained from a normalizer-canonical object produced by the corresponding canonical_bare_*/canonical_* function. A value derived from canonical_asu must first be projected to the required family and then passed through that family canonicalizer because projection and canonicalization do not generally commute. The renderer itself performs no affine-normalizer pass, so labels from hand-built, non-canonical objects are faithful but not necessarily canonical. Whenever text speaks of the label of an arbitrary value it uses the plain form (“the protostructure label”), reserving “the canonical … label” for a normalizer-canonical source.

The AFLOW-style -001 discriminators belong to a Prototype or a Protostructure (their discriminator field), which name a species-independent geometrical class. They are never part of the label.

Bonding-net labels¶

Protonettype and Protonetstructure extend a bare prototype or bare protostructure with a canonical descriptor of its symmetric covalent bonding net. The label is the bare label, __, the net, and for the assigned level the usual species suffix:

label      = bare_label "__" net [ ":" name { "-" name } ]
net        = group { "_" group }                  (may be empty)
group      = site [ shape ] [ "~" target { "." target } ]   (a shape, bonds, or both)
site       = digits                               (no leading zero)
shape      = uppercase letters, then the bond count, or I     e.g. OC6, TPRS9, I
target     = site [ "@" op [ "@" klm ] ]
klm        = digit digit digit                    (each digit = translation + 5)

The anonymous levels and the protonetstructure nest as string prefixes; the canonical bare protostructure label is not always one (see the species-order rule). For K₂AgSbS₄ (COD 1509425) with its Ag-S and Sb-S bonds, where no classes tie:

A4B2CD                                                                   Formulatype
A4B2CD_oP32_34_4c_abc_ab_c                                               BarePrototype
A4B2CD_oP32_34_4c_abc_ab_c__8I~1.2_9SS4~3.4_10~1.2.3.4@4                 Protonettype
A4B2CD_oP32_34_4c_abc_ab_c:S-K-Ag-Sb                                     BareProtostructure
A4B2CD_oP32_34_4c_abc_ab_c__8I~1.2_9SS4~3.4_10~1.2.3.4@4:S-K-Ag-Sb       Protonetstructure

What the parts are. Everything after __ describes which atoms are covalently bonded and how the bonds around each atom are arranged. The numbers are the symmetry-distinct sites of the prototype, counted in the order the label lists them: here 1-4 are the four S sites on 4c, 5-7 are K on 2a, 2b and 4c, 8-9 are Ag on 2a and 2b, and 10 is Sb on 4c. Each number stands for one reference atom of that site. Groups are separated by _. A group starts with a site number, then optionally that site’s shape (below), then ~ and the bonds the site lists. ~ means “is covalently bonded to” (bond order unspecified, dative bonds counted as covalent), and . separates the destinations. So 8I~1.2 says that site 8 has the shape I (irregular) and is bonded to site 1 and to site 2; it is a list, not a chain. A destination may carry @n, meaning the bond goes to the copy of that site’s reference atom produced by symmetry operation number n of the space group, not to the reference atom itself. A second @ adds a lattice translation as three digits, each being the shift along a, b, c plus 5, so 10@3@545 is operation 3 followed by one cell back along b. No @ means the reference atom itself, and a zero translation is never written. A reference atom is the first-listed Wyckoff coordinate at the site’s free parameters, not reduced modulo one.

Which site lists a bond. The bond count of a site is the number of atoms bonded to one of its atoms. A site is a top site when none of its bonded neighbours has a larger bond count. The sites are listed by larger bond count first, then top sites first, then smaller number, and each symmetry-distinct bond is listed once, from whichever end comes first in that order (a bond between copies of one site is listed there). Groups follow the listing order, and within a group the destinations follow the listing order of their sites, then the code. A site opens a group only if it lists a bond or has a written shape. So a polyhedron centre lists all its bonds, and its ligands open no groups of their own unless they have something left to say.

How to read it. Each entry is one symmetry-distinct bond, and all its symmetry copies are implied. The example therefore reads: Ag8 (shape I, an irregular site, here four-bonded) bonds to S1 and S2; Ag9 (a see-saw, SS4) bonds to S3 and S4; Sb10 (a tetrahedron, the default for four bonds, so not written) bonds to S1, S2, S3 and the image of S4 under operation 4 (x+1/2,-y+1/2,z+1/2). Those eight entries generate all 32 Ag-S and Sb-S bonds in the unit cell. The S sites, two-bonded and bent (A2, the default), open no group. Sites that appear nowhere, here the three K sites, have no covalent bonds. The net records covalent bonds only: a missing row means “no covalent bond”, not “no contact”. Which atom pairs are bonded is decided by the caller, who supplies the bond list (or by distance_bonds(), see Asymmetric units in detail); httk₂ does not infer it otherwise. The string is canonical: which symmetry copy serves as each site’s reference atom, and how interchangeable sites such as the four S are numbered, is chosen so that the string comes out smallest. Two crystals with the same prototype, the same bonding network and the same shapes get the same string, whatever their choice of origin and setting, and, outside P-1/P1 periodic nets (D7), the cell; the net depends on the coordinates only through the shapes.

Bond shapes¶

The shape of a site with two or more bonds is the arrangement of the bonds around one of its atoms: the directions to every atom it is bonded to. All atoms of a site have the same shape, and sites with fewer than two bonds have none. A named shape symbol ends in the bond count; the irregular symbol I has no count, which follows from the net. The symbols are the IUPAC polyhedral symbols without the hyphen where IUPAC defines one (N. G. Connelly et al. (eds.), Nomenclature of Inorganic Chemistry: IUPAC Recommendations 2005, section IR-9.3.2.1 and Table IR-9.2), the SHAPE program’s labels otherwise (M. A symbol is written only where it differs from the default of its bond count; a missing symbol means the default. Bond counts without a default (1 is never a shape; 10, 11, 13 and up) always write theirs, so an irregular site always writes I: 8I~1.2, or 3I for an irregular site that lists no bonds. The defaults are one table, and a change to it is a change of the net version. For five, seven and eight bonds the default is the most frequent shape on a sample of ICSD structures. A label is read under the net version it was written in: a label from another net version must not be parsed across versions, since its unwritten shapes mean other defaults (an unwritten eight-bonded site meant CU8 in net version 6 and means DD8 from net version 7). Net version 8 widened the supplied vocabulary (below) to every IUPAC polyhedral symbol and made I2 invalid; no label written under version 7 changed. Net version 9 writes irregular as I without its count (I4 became I), so every label with an irregular site changed; a written I<n> is refused with a message to write I.

The Source column names where a symbol comes from, not its geometry. The shapes that predate net version 7 keep geometries of their own; three of them deliberately differ from SHAPE’s reference coordinates (cosymlib, cosymlib/shape/ideal_structures_center.yaml): SPY5 (100 degrees between apex and base) is 5.0 degrees from SHAPE SPY-5, TPRS9 3.3 degrees from TCTPR-9, and PPY6 (an icosahedron vertex, its five neighbours and one outward bond) is not SHAPE’s PPY-6, whose coordinates are detected as TPR6 (14.6 degrees). TPRS7 is SHAPE’s reference geometry CTPR-7, taken about the central atom from the program’s own coordinates (D. Casanova et al., Chem. Eur. J. 9, 1281 (2003)). TPRT8 and HBPY9 are the undistorted constructions, which equal SHAPE’s ETBPY-8 and HBPY-9.

Supplied shapes. A person or another program can tell these shapes apart, so a supplied symbol may come from a wider vocabulary than the table: every IUPAC polyhedral symbol above, absent ones included, the SHAPE labels PPY6, COC12, ACOC12 and IC12, and I on any site of three or more bonds. I is never valid on two bonds, since two bonds are always L2 or A2. A symbol the baseline assigns names a class: DD8 from the detector covers every non-cubic eight-bond arrangement other than HBPY8 and TPRT8, a square antiprism included. A supplied symbol names the shape itself: a supplied SAPR8 is a square antiprism, and a label writes it as SAPR8. Two sources may therefore label one crystal differently. The network’s source and shapes_source tell the two apart: baseline shapes carry the software httk_basic. The code, labels, records and the exchange formats (the OPTIMADE _httk_bonds property and CIF) share one list of symbols, the named ones and I, and nothing is converted on writing or reading. The rule that a symbol’s number equals the atoms covered applies to the named symbols; I needs three or more.

Where shapes come from. A value states them: Protonettype(spacegroup, occupations, net, shapes) and its Protonetstructure counterpart take one symbol per site, None below two bonds, and require a supplied-vocabulary symbol on every site with two or more bonds: a named one ending in the site’s bond count, or I on three or more. Parsing a label fills in the defaults. A structure’s network may carry assigned shapes (the shapes of its BondNetwork, see Asymmetric units in detail), and from_asu with index-tuple bonds takes shapes=. Every other site gets the baseline: the angles between every pair of its bond directions, sorted, are compared with the sorted angles of each ideal shape of the same bond count by root mean square difference in degrees (rounded to 1e-6), and the closest shape wins (ties: table order); above 15 degrees, or for a count without ideal shapes, the site is I. Two bonds are L2 from 165 degrees, else A2. Bond lengths are not used. CIF _geom_bond_ networks use the baseline unless the file carries an httk _httk_shape_ loop. Some ideal shapes lie closer together than the 15 degree limit in this measure, so a slightly distorted polyhedron can be named after its neighbour: COC12/ACOC12 9.4, COC12/IC12 11.7, TP3/TPY3 13.0 and CU8/HBPY8 14.5 degrees. The closest shape still wins deterministically.

Description independence. The baseline reads exact quantities: the standard-setting metric of the structure averaged over the point group, and each exact squared cosine between two bonds converted to a float once. Every exact re-description of one crystal (cell, origin, setting, mirror image) therefore gives the same angles bit for bit, and the same shapes. The limits: crystals that are only approximately related (independently rounded files) are different exact crystals, and their shapes can differ where an angle, a misfit or a tie lies within rounding noise of a threshold; species classes merged by recognition use the recognized geometry; and math.acos is not correctly rounded, so platforms with different C maths libraries may differ in the last bit, which after the 1e-6 rounding changes a shape only for a value within about 1e-12 of a rounding boundary.

Relation to CIF. This is the CIF bond list in compressed form. CIF records a bond as two atom labels plus a symmetry code for each (_geom_bond_site_symmetry_1 and _2), written n_klm: operation number n, then the three translation digits offset by 5, with . for “no operation”. The 10@3@545 above is CIF’s 3_545 applied to the second atom, and the first atom’s code is always .. There are four differences. CIF’s operation number refers to the symmetry list inside that particular file, whereas here it refers to a fixed list for the space group’s standard setting, with the identity as number 1. CIF’s atoms are whichever ones the file happens to list, with coordinates, whereas here they are the reference atoms fixed by the canonical rule. CIF may list every bond around every atom, with distances, whereas here each symmetry-distinct bond appears exactly once, without distances, and every site with a non-default shape writes it. Finally, the redundant _555 is dropped.

Strictness. As for the other labels the parser is canonical-only (parse_protonettype_label and parse_protonetstructure_label in the notation module): it builds the value, re-renders it and rejects any string that differs, so 8~1@1, 8~1@3@555, 8~1., 8~1@3@55, a written default shape (10T4~...), a bond listed from the wrong end (1~8) and unsorted groups all fail. The following also hold.

  • A site number opens at most one group (several groups per site are reserved for several shapes on one site). A group needs a shape, bonds, or both: 3 alone is rejected.

  • An unknown shape symbol, a symbol whose number is not the site’s bond count, a symbol on a site with fewer than two bonds, and a missing symbol for a bond count without a default raise ValueError.

  • __ splits the bare label from the net at its first occurrence; neither part can contain __, since no field or group is empty, and a second __ is rejected. The species suffix is split off at the last :.

  • The characters -, =, #, $, :, / and \ are reserved inside the net for future bond types and are rejected.

  • A translation must lie in -5..+4 per axis, the range one digit can write. Input rows and bonds take any integer translation; only a canonical net that still needs a longer one raises ValueError (D4).

  • A well-formed but non-canonical net, such as the same bonds against other reference atoms or another numbering of interchangeable sites, is rejected: the parser’s value is canonical, so its label differs from the input.

  • An operation is written whenever a translation is, also operation 1 (10@1@655); operation 1 with zero translation is not written at all.

  • Operation n (1-based) is the n-th branch of the general Wyckoff position of the standard setting, with the identity as 1. This is not always the order of the International Tables: for group 34 the numbering is 1 x,y,z, 2 -x,-y,z, 3 -x+1/2,y+1/2,z+1/2, 4 x+1/2,-y+1/2,z+1/2, so 3 and 4 are exchanged. It is also not the order of Spacegroup.symmetry_operations, which for group 34 lists the identity last.

  • A pair of sites may repeat (7~1.1@3, two different bond orbits between the same two sites), and i~i@... is a bond between symmetry copies of one site (diamond: 1~1@14@654).

  • An empty net is written with a trailing __: AB_cF8_225_a_b__. Sites without bonds or a written shape do not appear in the net but keep their number.

The example below builds K₂AgSbS₄ from an exact asymmetric unit and an explicit bond list: the eight Ag-S and Sb-S bonds that a 3.0 angstrom cutoff finds, written (i, j, k, n1, n2, n3) against the input site order. The caller supplies the bonds; from_asu renumbers them into site order, takes the shapes from the baseline (or from shapes=, one symbol or None per input site) and returns the constructor’s value, with the net canonicalized. Bonds may carry any integer translation, so the free parameters need not be reduced into [0, 1). The asymmetric unit is the vendored COD entry; the label is pinned by tests/test_protonet_canonical_api.py.

from fractions import Fraction as F

from httk.atomistic import (
    ASUStructure,
    Cell,
    Protonetstructure,
    Species,
    WyckoffSite,
    canonical_protonetstructure,
)
from httk.core import FracVector

# K2AgSbS4 (COD 1509425, Pnn2, no. 34) as an exact asymmetric unit, sites in input order

A structure’s own bond network¶

An ASUStructure (or fundamental domain) can carry its bond network (see Asymmetric units in detail). Protonetstructure.from_asu(asu) and Protonettype.from_asu(asu) without a bond list use it, as do ProtonetstructureView(asu), ProtonettypeView(asu), canonical_protonetstructure(asu) and canonical_protonettype(asu); a structure without a network still raises there, since bonds are never recognized. The network is re-described with the structure first, so the structure may be in any setting and either hand:

from fractions import Fraction as F

from httk.atomistic import (
    AffineOperation,
    ASUStructure,
    Protonetstructure,
    SiteBond,
    Spacegroup,
    Species,
    WyckoffSite,
)

carbon = Species("C", ("C",), (1,))
cell = [[F(7, 2), 0, 0], [0, F(7, 2), 0], [0, 0, F(7, 2)]]
site = [WyckoffSite("a", (), "C")]
# diamond in origin choices 1 and 2 with its C-C bond, one spelling of the bond orbit in each
one = ASUStructure(cell, Spacegroup.from_setting("227:1"), site, [carbon],
                   bonds=[SiteBond(0, 0, AffineOperation("-x+1/4,-y+1/4,-z+1/4"))])
two = ASUStructure(cell, Spacegroup.from_setting("227:2"), site, [carbon],
                   bonds=[SiteBond(0, 0, AffineOperation("-x+3/2,z+1/4,y-1/4"))])
assert Protonetstructure.from_asu(one) == Protonetstructure.from_asu(two)

When two species share a class whose structure has higher symmetry than declared (COD 3000362, W-doped VO₂ declared P1 with four mixed V/W sites of one class, whose class structure is P2₁/c), the class structure is recognized and every bond pair is matched to its nearest atom there; the bonds are kept if the bond set is invariant under the recognized group, and otherwise from_asu raises ValueError naming that group. It raises too when two sites with different supplied shapes merge there.

Canonical protonet labels¶

One net is one value. The constructors Protonettype(...) and Protonetstructure(...), and from_asu, keep the anonymous bare description (no affine-normalizer pass, as for BarePrototype(...)) and canonicalize the net over site numbering, reference atoms and the equivalent descriptions with the same anonymous bare key, orientation-preserving, with the default timeout. Shapes travel with their sites; where interchangeable sites differ only in their shapes, the smaller symbol takes the smaller number. Two spellings of one net therefore give one equal value, and for a canonical bare part the constructor’s value is the canonical one.

At the assigned level the D3 tie-break may move species between the Wyckoff letters of those equivalent descriptions: Protonetstructure(225, [("a", Na), ("b", Cl)]) gives AB_cF8_225_a_b__:Cl-Na. This differs from BareProtostructure(...), which keeps any assigned description as given.

canonical_protonettype and canonical_protonetstructure return the canonical value for any protonet-like input. Both take preserve_chirality (as the bare canonicalizers do), timeout, the cooperative seconds allowed for the whole call, the bare part first and then the net search (default 120, None disables it), and on_limit: a call that exceeds the budget gives an undetermined label, or with on_limit="raise" raises CanonicalizationLimitError. A label string input is read as its own description, without the net search that parsing it would run; it is checked against the result afterwards, so a non-canonical label still raises ValueError when that can be decided within the budget. The net is chosen before the species. A canonical Protonetstructure is therefore canonicalized anonymously first, and species names only break ties between descriptions that give the identical net. When classes tie in site count and letters, its species-to-letter assignment, and so its label without the __net part, can differ from that of canonical_bare_protostructure(); no equality between the two is promised. Erasing a Protonetstructure to a Protonettype keeps class positions: class c becomes anonymous_symbol(c). In the monoclinic groups the search also chooses cells from the net, so no monoclinic net depends on the cell. In P-1 labels, and nets that are not periodic in any direction (molecular crystals), do not depend on the cell; P-1 nets with any periodic component are canonical only relative to the cell that httk’s standardisation chooses. P1 is excluded from the guarantee: it has no special positions, so its labels are unaffected, but its periodic nets stay canonical only relative to the cell (D7). See Canonicalization algorithms and reproducibility for the algorithm and its limits.

Species order of protonetstructure labels¶

A canonical Protonetstructure label is the canonical Protonettype label, :, and the species class names, which fill the classes in the class order of the canonical net. Where several descriptions give the same net, the smallest tuple of names is taken. The bare protostructure label instead orders tied classes by name alone. So BarePrototype → Protonettype → Protonetstructure nest as string prefixes, but BarePrototype → BareProtostructure → Protonetstructure do not always: cutting __net from a protonetstructure label gives a correct description of its bare protostructure, but not always the canonical bare protostructure label. The two orders differ when exchanging two species leaves the anonymous prototype label unchanged and the net tells them apart against alphabetical order. That happens when

  • two classes tie in site count and Wyckoff letters, or

  • an equivalent description exchanges their positions, e.g. two inversion centres of one Wyckoff set.

Undetermined labels¶

The protonetstructure label is a database row index, so a structure must get a label even when a part of it cannot be determined within the time budget. The six canonicalizers (canonical_bare_prototype(), canonical_bare_protostructure(), canonical_prototype(), canonical_protostructure(), canonical_protonettype(), canonical_protonetstructure()) and from_asu() take on_limit="undetermined" (the default) or "raise". With the default, a CanonicalizationLimitError inside the call gives an undetermined value of the same class instead. Its label has X in place of the first part that did not finish and of everything after it that depends on it; a label is built from left to right, and nothing already determined is discarded:

The last row is not reached in practice: recognition has no checkpoint (spglib cannot be interrupted), so a deadline that passes during it is noticed in the Wyckoff stage, which keeps the recognized group. <Formulatype>_X comes only from an explicit undetermined value or a limit raised while the input is converted.

The assigned levels append :<names>. For K₂AgSbS₄ (COD 1509425) a timeout in the Wyckoff part gives A4B2CD_oP32_34_X and A4B2CD_oP32_34_X__X:S-K-Ag-Sb, in the net alone A4B2CD_oP32_34_4c_abc_ab_c__X:S-K-Ag-Sb.

  • The Wyckoff part is the choice among equivalent descriptions. The space-group number and the Pearson symbol are kept whenever the symmetry analysis finished; with preserve_chirality=False the number is the lower enantiomorphic partner’s, as in the determined label. An undetermined Wyckoff part makes the net undetermined too, because the net’s site numbers follow the label.

  • After a determined bare part the names keep the bare protostructure label’s order (the canonical bare protostructure, see the previous section). Where the Wyckoff part is undetermined they are ordered by site count, largest first, then by name: K₂AgSbS₄ gives S-K-Ag-Sb.

  • The levels still nest as prefixes: A4B2CD, A4B2CD_oP32_34_X, A4B2CD_oP32_34_X__X, and A4B2CD, A4B2CD_X, A4B2CD_X__X.

  • The protonet canonicalizers take no structures, so the last row’s protonet label is built with Protonetstructure.undetermined(...) from an undetermined bare label.

  • X never stands in those positions of a determined label: the Formulatype starts with A, the Pearson symbol with a lower-case letter, a Wyckoff group is lower case, a net group starts with a digit, and no species class is named X.

Only CanonicalizationLimitError gives an undetermined label; invalid input still raises ValueError. The stages of one call share one budget (timeout; an enclosing budget still applies), so the net search gets what remains after the bare part.

Note

The bare and refined canonicalizers now take timeout too, and its 120 s default is a change of behaviour: they used to run without a deadline. Pass timeout=None for the old behaviour.

canonicalize() keeps raising, also for classification inputs, and so do the structure methods canonical_bare_protostructure() and canonical_bare_prototype() when their first step, canonical_asu, runs out; their bare stage can still return an undetermined value. from_asu keeps its constructor’s 120 s budget; a net that runs out bins with the canonical bare label, not with the input’s description (under an enclosing budget the bare part is canonicalized before the net search, so that it gets a share of the budget).

The determined part of an undetermined input is canonicalized too, with the call’s preserve_chirality: a determined bare part like any bare value (it keeps its __X), a Wyckoff-level label maps its number to the lower enantiomorphic partner with preserve_chirality=False (the Pearson symbol is unchanged), and a label without symmetry is returned unchanged. So AB_cF8_225_a_b__X:Na-Cl canonicalizes to AB_cF8_225_a_b__X:Cl-Na, as AB_cF8_225_a_b:Na-Cl does to AB_cF8_225_a_b:Cl-Na.

An undetermined value holds only its label text. determined is False; label, anonymous_formula, repr (Protonettype.undetermined('A4B2CD_X__X'), which round-trips), equality and hashing work; spacegroup, nsites_conventional and the Pearson symbol are known when the label names them, and occupations when it carries a determined bare part. Every other part raises ValueError naming determined; so does similar, which needs the geometry. A refined value whose geometry was not determined keeps neither its representative nor its discriminator: two such values with one bare label are equal. Its broader levels cut the label as the levels nest (the names for the anonymous levels, __X for the bare ones), so the canonicalizers and the views of those levels accept it: canonical_protonettype of A4B2CD_oP32_34_X__X:S-K-Ag-Sb is A4B2CD_oP32_34_X__X, and the bare_protostructure of A4B2CD_oP32_34_4c_abc_ab_c__X:S-K-Ag-Sb is the determined A4B2CD_oP32_34_4c_abc_ab_c:S-K-Ag-Sb. The public factories undetermined() (and alike on the other five classes) and the label parsers and views accept undetermined labels and parse them strictly, without a search: the space-group number as written by the renderer, a Pearson symbol of that group whose count fills its lattice points and whose primitive count is a multiple of the Formulatype’s, and the names. A determined bare part must be a canonical label string, as for determined bare labels; the canonicalizers then canonicalize it. Durable records store them in their undetermined field (identity-bearing when set; occupations and net then empty, the space-group fields set only when the label names the group).

Warning

Two undetermined values are equal when their labels are equal. That does not mean their structures or nets are the same: A4B2CD_oP32_34_X__X bins every structure whose Wyckoff part was not determined in that group and Pearson symbol, whatever its net.

No structure known in the fixtures exceeds the default budget any longer: the large molecules of the net search (D8) now finish in well under a second, and a molecular crystal such as COD 7218683 (22 sites in P2₁/c) is only undetermined under a short budget.

Structures that still get no label¶

Every other failure raises, as before (U1):

  1. Recognition finds no symmetry within tolerance, or spglib is missing (ImportError).

  2. Unsupported content: a species containing the unknown symbol X, assemblies, molecular=True at the assigned levels, a stated chemical_composition, site moments, or a cell that is not periodic in all three directions.

  3. Species without a class: a vacancy-only species, or a species whose constituents of one symbol sum to more than one site.

  4. Disorder at levels that refuse it: a refined Prototype of a disordered structure, and Structuretype.

  5. A retained imprecise WyckoffSite representative of a refined value.

  6. from_asu with bonds given as index tuples on a non-standard setting or with a retained site representative, a malformed or out-of-range bond, a self-bond, a structure without a bond network when no bonds are given, or species that share a class whose structure has more symmetry than the declared one under which the bond set is not invariant. A structure’s own network is read whatever site representatives it retains, since its reference atoms are the Wyckoff chart points.

  7. A canonical net that needs a translation outside −5..+4, which the notation cannot write (D4).

  8. Internal invariant failures: the net search and the bare canonicalization disagreeing on the bare prototype, or a table construction error.

  9. Limits on the lift=True paths and in canonicalize, which keep raising, and in canonical_asu as the first step of the structure methods canonical_bare_protostructure() and canonical_bare_prototype().

Similarity and atom travel¶

Prototype.similar and Protostructure.similar first compare their discrete space-group and occupation keys, then apply discriminator compatibility. If both values have representatives, the continuous comparison is the total Cartesian atom travel returned by the public structure_delta(first, second); missing representatives do not invent a distance. This method belongs to refined families; compare bare keys with equality. structure_delta maps the structures into a common subgroup and setting, pairs compatible Wyckoff orbits, and sums the shortest periodic Cartesian travel of their atoms. Each endpoint uses its own cell, so lattice changes contribute through the atom positions. It is not a content-id or label comparison. For compatible discrete keys and discriminators, geometrical comparison returns False when travel exceeds the budget or no common representation exists (NoCommonRepresentation, a ValueError subclass in httk.atomistic.symmetry.paths); other errors from a broken representative — a singular cell basis, a non-three-dimensional cell, or non-finite travel — propagate.

For approximate clustering, install httk-atomistic with its numpy extra and pass use_numpy=True to either similar(other, delta, use_numpy=True) or structure_delta(first, second, use_numpy=True). This converts each endpoint’s expanded coordinates once to temporary NumPy float64 arrays and computes orbit distance matrices with vectorized arithmetic. Storage for coordinates is linear in the expanded atom count; temporary distance matrices are limited to one orbit pair. The periodic-image search still handles skew cells, and atom/orbit assignment keeps the same minimum-cost matching. Discrete symmetry and canonicalization remain exact.

This option permits rounding differences in ties and near a comparison threshold, including variation across floating-point platforms. It also gives up exact cancellation before coordinate subtraction. The default comparison remains available. Neither mode modifies representatives, stored records, or content identity.

With use_numpy=True, similar uses conservative lower bounds to stop scoring an alignment that cannot meet delta. Rejection still considers the other allowed alignments; acceptance verifies travel in the returned setting. Roundoff allowances make rejection conservative without increasing the requested budget. structure_delta continues to compute the complete distance.

For repeated comparisons, pass the same httk.atomistic.symmetry.comparison_cache.StructureComparisonCache as cache= to similar or structure_delta. Preparation is lazy: the cache retains exact canonical structures and, with use_numpy=True, temporary float64 orbit arrays. Use one cache per clustering group and release it afterward, or call clear(). The max_structures and max_geometries capacities bound retained entries; eviction only repeats preparation and does not change comparison results. Different rerepresentation tolerances have separate canonicalization entries.

Each record carries the value identity of its family, so two equal values produce records with the same content id (the deduplication key) and unequal values differ. Bare records store only discrete classification. PrototypeRecord and ProtostructureRecord require a representative or discriminator, and store the optional representative as a nested record (FundamentalDomainTemplateRecord for a prototype, FundamentalDomainStructureRecord for a protostructure) and the optional discriminator as a plain column. Structuretype itself stays non-storable.

All four classification records render the httk label (for example AB_cF8_225_a_b and AB_cF8_225_a_b:Na-Cl) as a queryable label column. The content ids are unchanged by this — the label is a convenience and query column, not the record’s identity, and it is not unique: the discriminator is not part of the label, so records that share occupations but differ in class collide on it, and two protostructures whose species share a name but differ in another Species field also collide. Count and deduplicate by row (content id), never by label.

The bare registry records are atomistic-bare-prototype (family bare_prototypes) and atomistic-bare-protostructure (family bare_protostructures). The refined records are atomistic-prototype (family prototypes) and atomistic-protostructure (family protostructures), with atomistic-fundamental-domain-structure in the structures family. FundamentalDomainTemplateRecord is an embedded component record (nested inside PrototypeRecord as the optional representative) and deliberately has no registry entry of its own.

A store can retain one bare parent and multiple refined classes sharing its Wyckoff label. The COD canonicalization pass writes bare entries; discrimination writes refined entries and their bare parents to the final database, linked by bare content ID. These classification families need no OPTIMADE serving definitions to be saved and queried through storage APIs.

Development databases using the previous taxonomy must be rebuilt. No legacy registry aliases or upgrade machinery are provided.

The following are deliberately not part of this round and not part of the conversion contracts above:

  • OPTIMADE serving (definitions, providers, and bindings) for the prototype and protostructure families.

Grid candidate filtering¶

For a batch of geometry-carrying prototypes, protostructures, or exact structures in the same declared space group, use httk.atomistic.symmetry.comparison_grid.StructureComparisonGrid to avoid comparisons that cannot meet a Cartesian travel threshold:

from httk.atomistic.symmetry.comparison_cache import StructureComparisonCache
from httk.atomistic.symmetry.comparison_grid import StructureComparisonGrid

cache = StructureComparisonCache(max_structures=max(1, 2 * len(values)))
grid = StructureComparisonGrid(values, delta, dimensions=2, strategy="variance", cache=cache)
# Within the existing clustering loop:
if grid.might_match(i, j):
    matches = values[i].similar(values[j], delta, use_numpy=True, cache=cache)

The grid indexes one, two, or three Cartesian projections of expanded Wyckoff coordinates. It includes normalizer alternatives, periodic images, and repeated orbit members. first selects axes in order, variance prefers axes with larger coordinate variance, and occupancy prefers axes with more occupied scalar bins. These are selection strategies, not changes to the matching threshold. A grid candidate still needs the ordinary comparison; an excluded pair needs neither an assignment solve nor alignment scoring.

The necessary neighborhood radius follows the endpoint-cell travel metric: if an atom contributes at most delta, a candidate point must be within sqrt(2) * delta of a periodic image in the reference cell. Projecting that bound onto fewer coordinates admits extra candidates without removing valid ones. Numerical padding makes the filter conservative near float boundaries. Both alignment directions remain possible, and the retained exact representatives are unaffected.

Sparse buckets and a bounded query cache limit retained index data. max_points and max_images cap extra preparation and periodic-image work. Unsupported preparations, missing geometry, mixed groups, a zero threshold, or poorly conditioned cells fall back to unfiltered comparison; fallback_reason reports a group-wide fallback. selected_axes and indexed_points expose index diagnostics. Use the same shared cache for index construction and subsequent comparisons so canonicalization is reused. Index preparation may cost more than it saves for small or densely matching groups; benchmark complete groups when selecting settings.

Unified canonicalization¶

canonicalize(value) dispatches explicitly on the four classification backend families (including their views) and returns the matching standalone value. It is equivalent to canonical_bare_protostructure, canonical_bare_prototype, canonical_protostructure or canonical_prototype as appropriate, with the unified cooperative timeout option. Refined examples are transformed with their classification; discriminators are retained. Raw structure sources instead follow the measured structure path and return an ASUStructure. To canonicalize a bare classification derived from a structure, construct its bare view explicitly. See Canonicalization algorithms and reproducibility for the numbered algorithm and completion contract.
