httk.atomistic.models.structure.cif¶

A lossless CIF data block that is also a structure source.

CIFStructure keeps everything a CIF data block says (see CIFBlock) and converts to the other structure classes through CIFStructure.resolve(), which gives exactly what httk.core.load() gives for that block.

class httk.atomistic.models.structure.cif.CIFStructure[source]¶

Bases: httk.atomistic.io.cif.cif_items.CIFBlock, httk.atomistic.models.structure.backend.StructureBackend

A lossless, structure-like CIF data block.

It holds the block exactly as read_cif() reads it with lossless=True and is equal to another block with the same content. Any data block is one, also a block without atoms or a block that is not a valid structure: such errors appear only when it is converted. Conversion (resolve(), or constructing a structure view such as ASUStructureView(cs)) gives what httk.core.load() gives for the block, except that a data name the structure reader consumes may not occur twice. A fetched CIFStructureRecord becomes one with httk.core.coerce(record, CIFStructure).

The content rule, which decides equality and the content id: the content is the block name, the dialect, the file’s header, the leading comments, and the items in order (data names, values and comments in their places). Whitespace and quoting are not content (whitespace and line breaks outside text fields and strings, quote style, line ends, the encoding, a byte-order mark, trailing comment whitespace and blank lines), except that these four are content:

  1. a comment’s line placement, inline after a token or on its own line;

  2. quotes that change a value’s kind: '1.5' is a string and 1.5 a number, '?' a string and ? a gap;

  3. where the file header ends: a blank line before or among the leading comment lines ends the header, and the later comments lead the first block;

  4. runs of spaces inside a pragmatically joined value: P  21/c differs from P 21/c.

Inside a CIF2 list or table a comment’s placement is not content: it moves to just after the value.

Parameters:

  • name – The block name as written (after data_).

  • items – The block’s items in written order.

  • header – The file’s header comment lines.

  • leading – The own-line comments before the data_ line.

  • dialect – "cif" (read and converted as a .cif file) or "mcif" (as a .mcif file).

Raises:

ValueError – If a value, name or comment placement cannot be written in the block’s syntax.

resolve(*, repair=False, allow_large_cif_uncertainty=False)[source]¶

Convert the block to the structure httk.core.load() gives for it.

A "cif" block gives an ASUStructure (bonds included), an "mcif" block a SymopsStructure or ModulatedStructure. The default result is memoised.

Parameters:

  • repair (bool) – Apply the structure reader’s documented repairs, as load(..., repair=True).

  • allow_large_cif_uncertainty (bool) – Accept large stated uncertainties, as load(..., allow_large_cif_uncertainty=True) ("cif" blocks only).

Returns:

The structure.

Raises:

  • ValueError – If a data name the structure reader uses occurs more than once, or the block is not a valid structure (with the messages load gives).

  • TypeError – If allow_large_cif_uncertainty is given for an "mcif" block.
